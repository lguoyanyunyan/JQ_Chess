# 规则覆盖表

更新时间：2026-05-06

本文按当前 JavaFX 版工程能力整理规则覆盖情况。规则原文以 [藏族久棋最新规则.pdf](藏族久棋最新规则.pdf) 为基线；实际行为以 [当前实现状态](当前实现状态.md) 为准。

## 覆盖状态

| 规则/能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 传统基础 `14x14` 棋盘 | 已支持 | 规则配置统一给出棋盘尺寸、中心点和飞子阈值。 |
| 竞技化 `8x8` 棋盘 | 已支持 | 支持小棋盘、中心清空点和少于 `4` 子判负。 |
| 布子阶段 | 已支持 | 前两手必须落在中心斜线两端，之后双方轮流布满棋盘。 |
| 走子阶段 | 已支持 | 支持相邻移动、跳吃和连续跳吃。 |
| 成方补吃 | 已支持 | 成一个或多个 `1x1` 方后进入 `SQUARE_CAPTURE` 补吃。 |
| 飞子基础移动 | 已支持 | 当前行动方棋子数小于等于棋盘边长时，可飞到任意空点。 |
| 竞技化强势方单吃限制 | 已支持 | 对手具备飞子能力时，强势方跳吃不能以单吃结束。 |
| 重复局面和棋 | 已支持 | 规则层有重复局面计数和和棋判定。 |
| JavaFX `.jqj` 完整存档 | 已支持 | 保存规则模式、传统获胜阵型、AI 设置、阶段、当前方和棋盘状态。 |
| 旧文本棋盘读取 | 已支持 | 仅恢复 `0/1/2` 棋盘矩阵，不恢复完整对局上下文。 |
| 纯 Java AI | 已支持 | 支持布局、走子、飞子、成方补吃、基本阵型补吃和枪/煞补吃；评估按传统基础 / 竞技化 profile 分流，传统 profile 按当前选择的获胜阵型启用拉萨或金鱼目标启发，并叠加破门收益和飞子临界风险。 |
| native AI | 已支持 | Windows x64 下通过 JNA 调用随包 DLL。 |
| native AI + Java 校验 | 已支持 | native 返回后由 Java 规则层复核着法合法性。 |
| 基本阵型：褡裢 | 已支持 | 支持平门褡裢、斜门褡裢，仅传统基础模式触发。 |
| 基本阵型：双门褡裢 | 已支持 | 支持平口双门褡裢、斜口双门褡裢，仅传统基础模式触发。 |
| 基本阵型：拉萨 | 已支持 | 支持双门拉萨、三门拉萨，仅传统基础模式触发。 |
| 传统获胜阵型：拉萨 | 已支持 | 传统基础模式可选择拉萨为获胜阵型；只检查双门/三门拉萨。获胜还需强方棋子更多、弱方本手开始时未入飞子且结算后无棋门；本手未新形成拉萨时也会扫描强方是否已静态保持完整拉萨。 |
| 传统获胜阵型：金鱼 | 已支持 | 传统基础模式可选择金鱼为获胜阵型；使用 PDF 图17 原图转写的 14 子 offset 模板，允许旋转与镜像。金鱼只在被选为获胜阵型时影响胜负和传统 AI，不代表八吉祥整套制度已实现。 |
| 特殊阵型：枪 | 已支持 | 传统基础模式下，走一颗棋子后本方完整占据横向或纵向整线，可额外吃 `2` 子。 |
| 特殊阵型：煞 | 已支持 | 传统基础模式下，完整占据横向或纵向整线且同时形成单棋门或双棋门；普通成方吃子叠加阵型额外 `2` 子，总补吃 `3` 或 `4` 子。 |
| 其他特殊阵型 | 未支持 | 岚、三叉黑铁、恰、颂然涉及两/三颗同时移动或提本方任意一枚置于棋门，仍待扩展操作模型。 |
| 八吉祥阵型 | 部分支持 | 金鱼已作为单独传统获胜阵型接入；右旋海螺、宝瓶、宝伞、吉祥结、胜利幢、妙莲、法轮仍缺少可复核坐标模板，未进入规则识别、胜负判定或默认 AI 启发。 |
| 飞子阵型 | 未支持 | 十字飞子久、九子五久飞子久等仍缺少可复核坐标和特殊落点资料，未进入规则识别、胜负判定或默认 AI 启发。 |
| 完整传统胜负体系 | 部分支持 | 已支持拉萨和金鱼作为可选传统获胜阵型；固定棋形集合、八吉祥整套制度、让棋目标、吃子数量和积分制仍为后续工作。 |

## 验收口径

- 已支持：有规则层实现，并至少有 JUnit 自动化测试覆盖主要行为。
- 部分支持：配置、存档或 UI 已具备，但不会改变实际胜负或完整规则结果。
- 未支持：规则文档中存在，但当前程序不会识别、触发或判定。

## 发布说明口径

对外描述当前版本时，建议表述为：

> JavaFX 版已完成藏久棋三阶段基础对局、双规则模式、飞子基础移动、成方补吃、基本阵型 v1、特殊阵型枪/煞 v1、拉萨/金鱼可选传统获胜阵型、AI 对弈和完整存档。剩余特殊阵型、八吉祥其他阵型、飞子阵型及更完整传统胜负体系仍属于后续扩展。
