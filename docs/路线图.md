# 后续路线图

更新时间：2026-04-29

本文记录后续实现路线。已完成和未完成事项以 [当前实现状态](当前实现状态.md) 为准，规则来源以 [藏族久棋最新规则.pdf](藏族久棋最新规则.pdf) 为基线。

## 当前定位

当前项目已经完成三阶段基础对局：

- 布子阶段
- 走子阶段
- 成方后的补吃子状态
- 飞子基础移动
- 传统基础 / 竞技化规则模式
- WinForms native AI 与 JavaFX 纯 Java AI

项目还不是完整传统规则实现。剩余传统阵型、八吉祥阵型、飞子阵型和更完整传统胜负体系仍是后续工作。

## 第一阶段：三阶段基础对局

状态：已完成。

已落地内容：

- `14x14` 传统基础规则与 `8x8` 竞技化规则。
- 布满棋盘后清空中心两点并进入走子阶段。
- 相邻移动、跑吃、连续跳吃。
- 成方判定与补吃流程。
- 飞子基础规则，按当前行动方棋子数动态触发。
- 竞技化少于 `4` 子判负。
- 竞技化飞子阶段强势方跳吃不能单吃限制。
- AI 支持布局、走子和飞子基础状态。
- JavaFX 版 `.jqj` 完整存档和旧文本棋盘兼容读取。

## 第二阶段：规则测试与 JavaFX 稳定化

状态：进行中。

建议优先级最高，因为它能稳住后续规则扩展的地基：

- 为 `BoardState` 增加更多规则回归用例。
- 为 `FormationPatternDetector` 增加旋转、镜像、边界和误判测试。
- 为 `.jqj` 存档增加兼容性测试。
- 为 native AI 校验层增加非法返回串回归测试。
- 明确 WinForms 版与 JavaFX 版的功能差异，不再让两套实现的文档互相覆盖。

## 第三阶段：阵型吃子

状态：基本阵型 v1 与特殊阵型枪/煞 v1 已落地，更完整的特殊阵型和传统胜负体系仍待后续扩展。

已实现并通过自动化验收的基本阵型：

- 褡裢：平门褡裢、斜门褡裢
- 双门褡裢：平口双门褡裢、斜口双门褡裢
- 拉萨：双门拉萨、三门拉萨

已实现并通过自动化验收的特殊阵型 v1：

- 枪：走一颗棋子后本方完整占据横向或纵向整线，额外吃 `2` 子。
- 煞：完整占据横向或纵向整线且同时形成单棋门或双棋门，叠加普通成方吃子后总补吃 `3` 或 `4` 子。

当前工程行为：

- 仅在传统基础模式下触发基本阵型和枪/煞额外吃子。
- 阵型吃子与成方吃子共同进入 `SQUARE_CAPTURE`。
- JavaFX 纯 Java AI 可以生成带 `FC-` 的基本阵型和枪/煞补吃着法。

后续再扩展：

- 岚
- 三叉黑铁
- 恰
- 颂然

实现建议：

- 继续沿用统一阵型模板表示。
- 新增剩余特殊阵型前先补齐可编码坐标模板、验收局面和多子/提子操作模型。
- 明确每个剩余特殊阵型触发后的吃子数。
- 与成方吃子共同进入 `SQUARE_CAPTURE`。
- AI 评估中继续补充特殊阵型威胁和收益。

## 第四阶段：传统胜负体系

状态：传统获胜阵型 v1 已落地，当前支持选择 `拉萨` 作为获胜阵型；更完整的固定棋形、吉祥阵型、让棋目标和积分体系仍待扩展。

当前工程边界：

- 传统获胜阵型仅在传统基础模式下可选，竞技化模式强制归一为关闭。
- v1 下拉选项为 `关闭` / `拉萨`。
- 形成双门拉萨或三门拉萨后，需先完成对应补吃；形成方棋子更多、对方本手开始时尚未进入飞子阈值且结算后没有棋门时，才判形成方获胜。
- 若弱势方本手首次被吃到飞子阈值内，强势方本手未形成所选获胜阵型且弱势方仍有棋门，则按传统飞子临界裁定判弱势方胜。
- `.jqj` 使用 `traditionalWinningPattern` 保存；旧非关闭 `traditionalWinMode` 不再静默迁移。

后续可实现：

- 扩展更多可选获胜阵型。
- 八吉祥阵型识别与获胜。
- 让棋指定目标阵型。
- 传统定型、吃子数量和积分制的可配置化。

更完整的传统胜负体系仍适合在论文后续工作或扩展版本中说明，不建议在缺少测试样例时直接并入主流程。
