# 架构说明

更新时间：2026-04-29

本文说明当前仓库的代码结构、主要模块和实现边界。最新功能状态以 [当前实现状态](当前实现状态.md) 为准。

## 仓库结构

- `JQ/`
  - 原始 Windows 桌面实现。
  - `JQ/JQ/` 是 C# WinForms 主程序。
  - `JQ/jqai/` 是 C++ AI DLL。
  - `JQ/test/` 是历史辅助工具，不是正式测试套件。
- `JQJava/`
  - JavaFX 迁移实现。
  - `src/main/java/com/zangjiuqi/core/` 放规则、棋盘状态和合法性判断。
  - `src/main/java/com/zangjiuqi/ai/` 放纯 Java AI、native AI 适配和校验层。
  - `src/main/java/com/zangjiuqi/app/` 放 JavaFX 应用、存档和界面配置。
  - `src/test/java/` 是 JUnit 5 自动化测试。
- `docs/`
  - 规则、架构、AI、路线图、变更记录和资料索引。

## WinForms 版

WinForms 版由 `JQ/JQ.sln` 管理，主要工程包括：

- `JQ/JQ`
  - `Form_Main` 管理窗口、按钮、模式、搜索深度、超时和文件加载。
  - `MyPanel` 管理棋盘状态、鼠标交互、绘制、走法确认和 AI 调度。
  - `APiece` 表示棋子坐标和值。
  - `Move` 表示移动路径和被吃棋子。
- `JQ/jqai`
  - `ai.cpp` 是主要 AI 实现，包含走法生成、评估、搜索、哈希和 DLL 导出。
  - `ai.h` 声明 native 接口。

WinForms 版使用 C# 数组保存棋盘，界面层再把棋盘转换为 `0/1/2` 状态数组传给 C++ DLL。AI 返回字符串协议，例如 `A7`、`A1,A3,C3`、`TC-...`、`FC-...`。

## JavaFX 版

JavaFX 版是当前更适合继续演进的实现。它把规则、AI 和界面拆得更清楚：

- `BoardState`：棋盘状态机，覆盖布子、走子、成方补吃、飞子能力、胜负判定和存档恢复。
- `BoardRuleConfig`：规则配置，按模式给出棋盘尺寸、飞子阈值、阵型吃开关和传统获胜阵型。
- `RuleMode`：`TRADITIONAL_BASIC` 为 `14x14`，`COMPETITIVE` 为 `8x8`。
- `FormationPatternDetector`：阵型模板匹配入口，当前用于传统基础模式的阵型吃子扩展。
- `JavaAiEngine`：纯 Java 搜索 AI，带局面 key、评估和走法生成。
- `NativeAiClient`：JNA 调用 `jqai.dll` 的适配层。
- `ValidatingAiClient`：用 Java 规则层校验 native AI 返回的着法。
- `GameSaveService`：读写 `.jqj` 完整存档，并兼容旧文本棋盘。

## 规则状态机

当前规则状态可以概括为：

- `EMBATTLE`：布子阶段，双方轮流在空点放子。
- `MOVE`：走子阶段，允许相邻移动、跳吃和飞子移动。
- `SQUARE_CAPTURE`：成方或阵型触发后的补吃阶段。

飞子不是单独全局阶段，而是按当前行动方棋子数动态判断。传统基础模式阈值为 `14`，竞技化模式阈值为 `8`。

## AI 架构

本仓库同时保留两套 AI：

- C++ native AI：搜索深、速度快，是 WinForms 版的历史主力。
- 纯 Java AI：便于 JavaFX 版跨平台运行、测试和规则校验。

JavaFX 版默认使用纯 Java AI。用户也可以选择 native AI，或选择“native AI + Java 校验”，让 Java 规则层在执行前复核 native 返回结果。

纯 Java AI 的搜索框架仍是 `negamax + alpha-beta + transposition table`，`JavaAiEngine` 只负责搜索、缓存、超时和合法着法遍历；局面评估、走法排序和根节点战术加成由 `AiStrategyProfile` 提供。当前有两个 profile：`CompetitiveAiProfile` 面向竞技化规则，保持材料、吃子和即时战术权重；`TraditionalAiProfile` 面向传统基础规则，增加目标阵型、破门和飞子临界启发。

传统阵型目标不写死在搜索引擎里，而是通过 `TraditionalPatternHeuristic` 组合。`PatternShape` / `PatternShapeScanner` 负责 AI 模板点位、旋转镜像、边界扫描和进度统计；core 层另有静态模板扫描用于所选传统获胜阵型判断。当前拉萨和金鱼共用 core 模板资料，前端选择哪个获胜阵型，规则胜负和传统 AI 目标就只围绕哪个阵型。后续八吉祥其他阵型、让棋目标或飞子阵型可继续添加模板和 heuristic。

## 数据与存档

- JavaFX 版完整存档扩展名为 `.jqj`，包含规则模式、传统获胜阵型、AI 后端、棋盘状态、阶段和当前方。
- 旧 `0/1/2` 文本棋盘仍可读取，但只能恢复棋盘矩阵，不能恢复完整对局上下文。
- WinForms 版仍沿用历史文本局面与本地 DLL 工作方式。

## 已知架构边界

- WinForms 版 UI 与规则逻辑耦合较重，继续扩展高阶规则时维护成本较高。
- C++ AI 仍使用 C 风格字符串协议，后续可考虑结构化协议或 Java 规则层作为统一校验边界。
- JavaFX 版已支持选择拉萨或金鱼作为传统获胜阵型，并按强方棋子更多、弱势方本手开始时未入飞子且结算后无棋门的条件判定；本手未新形成所选阵型时，也可在结算后扫描强势方是否已静态保持所选阵型。同时支持弱势方首次入飞子阈值且仍有棋门、强方未形成或保持所选阵型时的传统临界胜；更完整的固定棋形集合、八吉祥整套制度、让棋目标和积分制仍需要继续实现。
