# 演示脚本 v1

更新时间：2026-04-30

本文给出 JavaFX 版阶段性交付演示流程。演示时建议默认使用纯 Java AI，避免 native DLL 或平台差异影响展示。

## 路径一：竞技化 8x8 对局

目标：展示当前程序的基础可玩性、小棋盘规则和 AI 后端。

步骤：

1. 启动 JavaFX 版。
2. 规则选择 `竞技化`，模式可选 `人机对战` 或 `机机对战`。
3. AI 后端选择 `纯 Java AI`。
4. 点击重新开始，展示 `8x8` 棋盘、状态摘要和当前轮次。
5. 进行若干步走子，说明竞技化模式下传统获胜阵型会自动关闭。

讲解要点：

- 竞技化模式使用 `8x8` 棋盘。
- 飞子阈值按棋盘边长计算。
- 竞技化仍保留少子方保护规则：对手具备飞子能力时，强势方跳吃不能以单吃结束。

## 路径二：传统基础 14x14 阵型补吃

目标：展示传统基础模式、成方补吃、基本阵型和枪/煞阵型补吃。

步骤：

1. 规则选择 `传统基础`。
2. AI 后端选择 `纯 Java AI`，AI 深度保持默认或降低到便于演示的值。
3. 展示右侧状态摘要中的 `14x14`、阶段、轮到方和获胜阵型选项。
4. 使用预设或测试局面演示阵型触发后的补吃流程。
5. 当进入补吃阶段时，展示状态摘要中的 `待补吃` 和 `阵型` 信息。

讲解要点：

- 基本阵型 v1 包括褡裢、双门褡裢、双门拉萨、三门拉萨。
- 特殊阵型 v1 支持枪、煞。
- 阵型吃子和普通成方吃子共同进入补吃流程，AI 着法仍通过 `FC-` 表示补吃。

## 路径三：传统获胜口径说明

目标：说明当前传统获胜阵型由前端选择驱动，并解释强势方获胜与弱势方临界反胜。

步骤：

1. 规则选择 `传统基础`。
2. 获胜阵型选择 `拉萨` 或 `金鱼`。
3. 展示 UI 提示：只按当前选择的获胜阵型判胜和引导传统 AI；强方更强、对方本手开始时未入飞子且结算后无棋门，则强方胜。
4. 说明另一个裁定：弱势方本手首次入飞子阈值且仍有棋门、强势方未形成也未保持所选阵型，则弱势方胜。
5. 展示或引用自动化测试覆盖的结束原因：
   - `传统获胜阵型：拉萨`
   - `传统获胜阵型：金鱼`
   - `传统飞子临界：弱势方保有棋门`

讲解要点：

- 当前口径不是完整传统胜负体系。
- 当前只支持拉萨和金鱼作为可选获胜阵型，不支持八吉祥整套制度、让棋目标阵型或积分制。
- 弱势方飞子临界保门胜来自 PDF 中“弱势方还有棋门，则算弱势方胜”的工程化解释。
