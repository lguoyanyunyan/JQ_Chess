# 当前实现状态

更新时间：2026-04-22

## 规则模式

当前程序支持两种规则模式：

- 传统基础规则：`14x14` 棋盘，共 `196` 个交叉点。
- 竞技化规则：`8x8` 棋盘，共 `64` 个交叉点。

规则切换只在新开局或读档前生效，不支持一局中途切换棋盘尺寸。

## 棋盘尺寸配置

棋盘尺寸由规则配置统一决定：

- 传统基础：`BoardSize = 14`，飞子阈值 `14`。
- 竞技化：`BoardSize = 8`，飞子阈值 `8`。
- 布局完成后的中心清空点按尺寸计算：
  - `14x14`：`(6,6)`、`(7,7)`
  - `8x8`：`(3,3)`、`(4,4)`

竞技化少于 `4` 子判负规则保持不变。

## 界面与读档

- 棋盘绘制区域仍使用原有 `700x700` 区域。
- 交点间距、点击命中、棋子直径、行列编号都按当前棋盘尺寸动态计算。
- 传统基础显示 `A-N` 与 `1-14`。
- 竞技化显示 `A-H` 与 `1-8`。
- 读档按当前规则校验尺寸：
  - 传统基础只接受 `14x14`。
  - 竞技化只接受 `8x8`。

## AI 接口

AI DLL 当前保留两个入口：

- `getAIMove(...)`：旧接口，按 `14x14` 兼容。
- `getAIMoveEx(..., boardSize, ...)`：尺寸感知接口，当前支持 `8` 和 `14`。

C# 调用 AI 时会按当前规则传入 `boardSize`，并传入对应长度的一维棋盘数组。

## AI 行为

- C++ AI 会按运行时棋盘尺寸生成相邻连接表和 `2x2` 成方表。
- 现有 `14x14` 开局形状启发只在 `boardSize == 14` 时使用。
- `8x8` 当前没有外部开局库，使用通用搜索与评估。
- 飞子移动本身不能跳吃；只有成方补吃才能吃子。
- 当 AI 调用在 `8x8` 和 `14x14` 之间切换时，会清空哈希表。

## AI 非法着法防护

已处理 AI 返回非法着法的问题：

- 修复 `make_final_move()` 中对手着法数组误用。
- 哈希表 key 已加入 `side`、`rule`、`phase`、`board_width` 上下文。
- AI 返回前会使用传入 DLL 的真实棋盘复核 `best_move`。
- C# 执行 AI 着法前也会校验坐标、起点、终点和吃子列表。

如果 DLL 后续仍返回非法路径，界面会提示 `AI 返回非法着法`，不会再破坏棋盘状态。

## 已验证

- `Debug|x64` 解决方案构建通过，`0` 错误。
- `Release|x64` 解决方案构建通过，`0` 错误。
- `jqai.dll` 导出包含 `getAIMove` 与 `getAIMoveEx`。
- 空棋盘 DLL 探测：
  - `8x8=D4`
  - `14x14=G7`
- 截图近似局面 DLL 探测：
  - `side0=A8,A7`
  - `side1=A1,A2`

## 已知限制

- 阵型吃、吉祥阵型、完整传统胜负体系尚未全部实现。
- 目前缺少自动化规则回归测试。
- C++ 项目仍保留旧 C 字符串 API 警告，例如 `sprintf`、`strcat`、`strcpy`。
- WinForms AI 线程仍沿用旧结构，后续如继续扩展建议单独治理线程与 UI 调用安全。
