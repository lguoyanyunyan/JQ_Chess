# 当前实现状态

更新时间：2026-04-29

本文记录当前代码实际支持的功能。规则资料和历史说明如果与本文冲突，以本文为准。

## 项目形态

当前仓库包含两个实现：

- WinForms 版：`JQ/JQ.sln`，C# 界面 + C++ `jqai.dll`。
- JavaFX 版：`JQJava/pom.xml`，JavaFX 界面 + 纯 Java AI，可选 native AI。

JavaFX 版规则层、AI 校验和自动化测试更完整，后续扩展建议优先以 JavaFX 版为主线。

## 规则模式

当前程序支持两种规则模式：

- 传统基础规则：`14x14` 棋盘，共 `196` 个交叉点。
- 竞技化规则：`8x8` 棋盘，共 `64` 个交叉点。

规则切换只应在新开局或读档前进行，不支持一局中途切换棋盘尺寸。

## 棋盘尺寸配置

棋盘尺寸由规则配置统一决定：

- 传统基础：`BoardSize = 14`，飞子阈值 `14`。
- 竞技化：`BoardSize = 8`，飞子阈值 `8`。
- 布局完成后的中心清空点按尺寸计算：
  - `14x14`：`(6,6)`、`(7,7)`
  - `8x8`：`(3,3)`、`(4,4)`

竞技化少于 `4` 子判负规则已实现。

## 对局阶段

当前实现覆盖：

- 布子阶段：双方轮流落子。
- 走子阶段：相邻移动、跑吃、连续跳吃。
- 成方补吃阶段：成方后移除指定数量的对方棋子。
- 飞子基础能力：当前行动方棋子数小于等于阈值时，可飞到任意空点。

飞子不是独立全局阶段，而是按当前行动方棋子数动态判断。

## 阵型与传统胜负

当前状态：

- JavaFX 版已经有 `FormationPatternDetector` 和传统胜负模式枚举。
- 传统基础模式下可为阵型吃子保留入口。
- 固定棋形获胜、首个吉祥阵型获胜、让棋指定阵型获胜等模式已有 UI/配置表达，但实际胜负判定仍待完整阵型识别支持。

尚未完整落地：

- 全量基本阵型识别。
- 特殊阵型识别。
- 吉祥阵型识别。
- 飞子阵型。
- 完整传统胜负体系。

## AI

当前 AI 形态：

- WinForms 版主要调用 C++ `jqai.dll`。
- JavaFX 版默认使用纯 Java AI。
- JavaFX 版也可选择 native AI，或选择 native AI + Java 校验。

C++ AI DLL 保留两个入口：

- `getAIMove(...)`：旧接口，按 `14x14` 兼容。
- `getAIMoveEx(..., boardSize, ...)`：尺寸感知接口，支持 `8` 和 `14`。

已处理的 native AI 非法着法风险：

- 修复对手着法数组误用。
- 哈希表 key 加入 `side`、`rule`、`phase`、`board_width` 上下文。
- AI 返回前使用真实棋盘复核候选走法。
- C# / Java 执行层在执行前校验坐标、起点、终点和吃子列表。

## 存档

JavaFX 版：

- 完整存档使用 `.jqj`。
- `.jqj` 保存规则模式、传统胜负模式、AI 后端、阶段、当前方和完整棋盘状态。
- 旧 `0/1/2` 文本棋盘仍可读取，但只能恢复棋盘矩阵，不能恢复完整对局上下文。

WinForms 版：

- 仍沿用历史文本局面和本地 DLL 运行方式。

## 已验证

- JavaFX 版存在 JUnit 5 自动化测试。
- Maven 配置使用 Java 17、JavaFX 17.0.10、JUnit 5.10.2。
- Windows 打包脚本会先运行测试，再执行 `mvn -q -DskipTests package` 和 `jpackage`。
- C++ `jqai.dll` 已包含尺寸感知入口 `getAIMoveEx`。

## 已知限制

- 完整传统阵型和传统胜负体系仍待实现。
- WinForms 版 UI 与规则逻辑耦合较重，后续大规模规则扩展不建议继续只改 WinForms 版。
- C++ native AI 仍使用 C 风格字符串协议。
- 自动化规则测试还需要覆盖更多边界局面和 native AI 非法返回场景。
